Two nixpkgs packages. Pick the higher one. Most rounds ask how much of nixpkgs would have to rebuild if the package changed: the number of packages with it somewhere in their build graph. The rest ask about runtime closure size, how many versions nixpkgs has shipped, and which was packaged first. After each answer, both cards show their store path and a command that reproduces the number.

    How the numbers were measured

    Rebuilds: nixpkgs was evaluated for x86_64-linux with nix-eval-jobs, which walks the same attributes as nix-env -qa, package sets such as python3Packages included. Every input derivation of every .drv was then followed through the store. A package's count is how many of the evaluated packages (distinct derivations, so aliases count once) have its .drv anywhere in their build closure. Change it, and each of those gets a new hash and has to be built again.

    No single command prints that count, so each card names one of the packages it covers, with the nix why-depends --derivation command that shows the chain between them. The whole count can be redone by hand, slowly, with one nix-store -qR per evaluated package: 

    rev=
src=$(nix flake prefetch --json "github:NixOS/nixpkgs/$rev" | jq -r .storePath)
nix-eval-jobs --workers 4 --max-memory-size 3072 --expr \
  "import $src { system = \"x86_64-linux\"; config.allowUnfree = true; }" > eval.jsonl
jq -r '.drvPath // empty' eval.jsonl | sort -u > drvs.txt
target=$(nix eval --raw "github:NixOS/nixpkgs/$rev#libndp.drvPath")
while read -r drv; do
  [ "$drv" != "$target" ] && nix-store -qR "$drv" | grep -qxF "$target" && echo "$drv"
done < drvs.txt | wc -l

    docs/data.md explains how the pipeline does the same for every package at once.

    The count is for the attribute itself. gcc is the wrapped compiler stdenv uses, so nearly everything counts it. stdenv's shell is bashNonInteractive, so bash, the interactive build, counts only the packages that ask for it by name.

    Closure size: the sum of NarSize over the runtime closure of the package's default output, read from cache.nixos.org's narinfos, the number nix path-info -S prints. "Check it live" repeats the walk from this page. Packages the cache does not have, such as unfree ones, never come up in a closure round.

    Versions and first seen come from nixpkgs-multiverse, which records every version each attribute had at each nixos-unstable channel bump since 2012. A version that came and went between two bumps is not counted. The index has no revisions between October 2013 and September 2016, so a package added then is only known to have arrived somewhere in that window. Two packages are only compared when their windows are at least six months apart.

    Pools: the common pool is the top-level packages with the highest rebuild counts, build plumbing removed, plus a hand-kept list of applications nothing depends on. The daily game draws only from it. Deep cuts is packages: the common pool, then the rest ranked by rebuild count and, among the many with none, by how many versions nixpkgs has shipped.

    Pairs are drawn so the answer is neither a coin flip nor a blowout. The daily game is drawn from the date alone, so everyone playing on the same day gets the same ten rounds. Use 1 and 2 or the arrow keys to pick, Enter to go on.
